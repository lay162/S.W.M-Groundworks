--------------------------------------------------------------------------------
1) ENABLE GITHUB PAGES
--------------------------------------------------------------------------------
1. GitHub → repository **S.W.M-Groundworks** → **Settings** → **Pages**.
2. Under **Build and deployment** → **Source**: choose **GitHub Actions** (not “Deploy from a branch” for this workflow).
3. Push to **main** (or open **Actions** → **Deploy GitHub Pages** → **Run workflow**). The first successful run publishes the site.
4. Your temporary URL will look like: **https://lay162.github.io/S.W.M-Groundworks/** (user + repo name; dots in the repo name are kept).

--------------------------------------------------------------------------------
2) SECRETS & VARIABLES (quote form → Google Sheet)
--------------------------------------------------------------------------------
The built JavaScript needs your Apps Script URL and shared secret at **build time** (they are embedded in the bundle —
anyone can read them in DevTools, same as any client-side form; use a long random secret and optional throttling in the script).

GitHub → **Settings** → **Secrets and variables** → **Actions** → open the **Secrets** tab (not “Environments”).

Click **New repository secret** and add (names must match exactly):

  Required:
    VITE_GOOGLE_APPS_SCRIPT_URL     = your Apps Script Web App URL (ends with /exec)
    VITE_GOOGLE_APPS_SCRIPT_SECRET  = same value as SECRET in Code.gs (no surrounding ' quotes)

  Optional:
    VITE_GOOGLE_APPS_SCRIPT_INCLUDE_PHOTOS = true   (only if you send photos to Drive from the browser)
    VITE_BUSINESS_QUOTE_EMAIL              = your public email (mailto fallback)

Do **not** create an **Environment** whose name is `VITE_GOOGLE_APPS_SCRIPT_URL` — that is a variable *name*, not an environment. If you made one by mistake, delete it (trash icon on **Settings → Environments**). Keep only **github-pages** (GitHub creates/uses it for Pages deploy).

Do **not** put the script secret under **Environment variables** (values are visible). Always use **Repository secrets** for the two VITE_* keys above.

After changing secrets: **Actions** → re-run the latest workflow, or push an empty commit, so a new build runs.

Local dev: copy **.env.example** to **.env** and fill the same `VITE_*` names, then `npm run dev`.

--------------------------------------------------------------------------------
3) APPS SCRIPT (GOOGLE SHEETS)
--------------------------------------------------------------------------------
Use **FOR-GOOGLE-APPS-SCRIPT-PASTE-ONLY.txt** and **google-apps-script.txt**. Deploy the script as a Web app with access
**Anyone** (or “Anyone with Google account” if you accept sign-in only — then browser POSTs may fail for anonymous visitors).

**CORS:** The site sends POST with **Content-Type: text/plain** (required for Apps Script from GitHub Pages). If rows still do not appear:
- Redeploy the Web app as a **new version** after editing the script.
- Ensure the request URL is the **current /exec** URL from **Deploy** → **Manage deployments**.
- Confirm **VITE_GOOGLE_APPS_SCRIPT_SECRET** in GitHub matches **SECRET** in Code.gs exactly.

If POST still fails, the app falls back to **mailto** to **quotes@swm-groundworks.co.uk** (photos do not attach in that path). Set up a Zoho filter on subject **Quote request** so mailto and Apps Script mail both land in your Quotes folder.

--------------------------------------------------------------------------------
4) CUSTOM DOMAIN (e.g. swm-groundworks.co.uk from Namecheap)
--------------------------------------------------------------------------------
When you own **swm-groundworks.co.uk**:

1. GitHub → repo → **Settings** → **Pages** → **Custom domain**: enter **swm-groundworks.co.uk** (and add **www** if you use it).
2. GitHub shows the **DNS records** to add at Namecheap (**Advanced DNS**). Typical pattern:
   - **A** records for **@** → GitHub’s IPs (copy from GitHub; they can change — always use GitHub’s current list).
   - **CNAME** for **www** → **lay162.github.io** (your GitHub username + .github.io).
3. Wait for DNS (minutes to 48h). **Enforce HTTPS** stays on in GitHub Pages.
4. **index.html** canonical / **og:url** / JSON-LD **url** are set to **https://swm-groundworks.co.uk/** — update that file if you use a different hostname.

**apex vs www:** Many registrars make **www** easier; you can redirect **@** → **https://www.swm-groundworks.co.uk** at Namecheap and set the GitHub custom domain to **www**.

--------------------------------------------------------------------------------
5) SPA REFRESH (404 ON DEEP LINK)
--------------------------------------------------------------------------------
The workflow copies **dist/index.html** to **dist/404.html** so client-side routes survive a full page refresh on GitHub Pages.

--------------------------------------------------------------------------------
6) LEAVING NETLIFY (STOP USAGE EMAILS / BANDWIDTH)
--------------------------------------------------------------------------------
This repo deploys **only** via **.github/workflows/github-pages.yml** → GitHub Pages. There is **no** netlify.toml,
netlify/functions, or Netlify CLI in the project. DNS for **swm-groundworks.co.uk** points to GitHub Pages (185.199.x.x),
not Netlify — so live traffic is **not** served by Netlify.

If Netlify still emails you about usage (e.g. 50% bandwidth), the old Netlify **site/account** is probably still active
and may still be building from Git pushes. Do this once in the Netlify dashboard (app.netlify.com):

1. Open the old **S.W.M Groundworks** site (or any site linked to this repo).
2. **Site configuration** → **Build & deploy** → **Continuous deployment** → **Disconnect** Git repository.
   (This stops auto-builds on every push — the main cause of ongoing usage.)
3. Optional but recommended: **Site configuration** → **Domain management** → remove **swm-groundworks.co.uk** / **www**
   if they are still listed on Netlify (DNS already points to GitHub).
4. To stop all Netlify usage for this project: **Site configuration** → **General** → **Danger zone** →
   **Delete site**.
5. Revoke Netlify GitHub access: **GitHub** → **Settings** → **Applications** → **Netlify** → **Revoke** (if listed).

After disconnect/delete, usage should drop to zero for this site. New deploys happen only when **main** pushes trigger
**Actions** → **Deploy GitHub Pages** in this repo.
